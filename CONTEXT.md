### What Exists (committed and working)

Key top-level packages: `src/auth`, `src/client`, `src/models`, `src/portfolio`, `src/paper`, `src/mf`, `src/dhan`, `src/nuvama`, `src/intraday`, `src/instruments`, `src/market_calendar`, `src/notifications`, `src/utils`, `src/backtest`, `src/risk`, `src/gamma`, `src/strategy`, `src/council`, `src/db.py`
`src/risk/` — portfolio-level delta risk controls. `PortfolioDelta` frozen dataclass (`src/risk/models.py`): `options_delta_lots`, `niftybees_delta_lots`, `total_delta_lots`, `warning_breached`, `cap_breached`, `as_of`. `PortfolioDeltaTracker` (`src/risk/delta_tracker.py`): `aggregate_delta(paper_positions, nifty_spot, lot_size, position_deltas=None) → PortfolioDelta`; options-only thresholds warning=0.75/cap=1.0 lots, combined thresholds warning=1.5/cap=2.0 lots; parameterised via constructor. Classification is by `PaperPosition.option_type` (not `instrument_key` substring — fixed in BUG-002/B002.3, real Upstox keys are numeric-only). If `position_deltas` (dict, `instrument_key` → signed delta-in-lots) supplies a chain-derived value for a PE/CE leg, that value is used as-is (B002.4); otherwise falls back to the approximation CE=`net_qty/lot_size`, PE=`-net_qty/lot_size` with a logged WARNING (never silent — module stays pure/zero-I/O per council ruling `docs/council/2026-07-02_paper-delta-source-architecture.md`, caller is responsible for resolving the map). FUT = `net_qty/lot_size`; NiftyBees = `qty×avg_cost/(spot×lot_size)`; unresolved `option_type` → WARNING + zero delta (never misclassified as a future). `check_entry_allowed` (`src/risk/entry_gate.py`): protective entries always allowed; cap → block; warning → allow with message. 33 unit tests in `tests/unit/risk/test_delta_tracker.py` + hypothesis property tests in `tests/unit/risk/test_delta_hypothesis.py`.
`src/gamma/` — scaffolding, data models (`GammaChainSnapshot` and `GammaWatchlistEntry` frozen dataclasses), and persistence (`GammaStore` SQLite operations) for Near-Expiry Gamma Buy strategy.
`src/backtest/ivr.py` — `compute_ivr(vix_today, vix_series)`: IVR formula over trailing 252-day VIX window; returns `float | None`; clamps to `[0.0, 1.0]`; flat-window safe (returns 0.5). 11 unit tests in `tests/unit/backtest/test_ivr.py`.
`src/backtest/vix_ingest.py` — India VIX ingestion pipeline. Supports NSE CSV (legacy) and Upstox API.canonical Parquet storage: `data/historical/ohlc/india_vix/`. Resumable — identifies gaps and fetches missing days. 7 unit tests in `tests/unit/backtest/test_vix_ingest.py`.
`src/backtest/chain_writer.py` — `ChainWriter` class for EOD and intraday chain snapshot Parquet writes. Both `write_eod_snapshot`/`write_intraday_snapshot` take a `label` param (e.g. "monthly"/"quarterly"/"yearly", default `"default"`) appended to the output filename — required to disambiguate multiple expiries snapshotted in the same run; without it, same-timestamp writes for different expiries silently overwrote each other (BUG-006, fixed SHA 7e0801c). 14 unit tests in `tests/unit/backtest/test_chain_writer.py`.
`src/backtest/chain_reader.py` — `ChainReader` class for DuckDB-based option chain EOD and intraday query scan utilities. 8 unit tests in `tests/unit/backtest/test_chain_reader.py`.

`src/models/options.py` — `OptionLeg`, `OptionChainStrike`, `OptionChain` (all `frozen=True` Pydantic). Source-agnostic field names; Upstox parser in `src/client/upstox_market.py` (`parse_upstox_option_chain`). Dhan parser not implemented (chain-data story complete; Dhan approach not pursued).
`src/paper/` — paper trading module. `TradeState` enum (`OPEN`/`DEFENDED`/`RE_ENTRY_PENDING`) in `models.py`. `PaperTrade` model (frozen Pydantic, `paper_` prefix enforced, includes `ivr_at_entry: float | None`, `state: TradeState = OPEN`), `PaperPosition` + `PaperNavSnapshot` + `PaperLegSnapshot` (frozen dataclasses) — `PaperPosition.option_type: Literal["PE","CE","FUT","EQ"] | None` (B002.3) resolved lazily by `PaperStore.get_position`/`get_positions` via `InstrumentLookup`, not stored; `NIFTYBEES_KEY` short-circuits to `"EQ"`; falls back to `None` (logged WARNING, never raises) on unresolved key, missing/corrupt BOD JSON, or a resolved `instrument_type` outside CE/PE/FUT. `PaperStore` constructor takes an optional `instrument_lookup: InstrumentLookup | None` param for this (lazily built from `DEFAULT_BOD_PATH` if not injected; not thread-safe). `PaperStore` (`paper_trades` + `paper_nav_snapshots` + `paper_leg_snapshots` + `pending_approvals` + `council_outputs` + `daemon_heartbeat` + `paper_exit_events` tables in shared SQLite), `PaperTracker` (compute_pnl + record_daily_snapshot). `PaperStore` API: `record_leg_snapshot` (upsert; enforces `total_pnl == unrealized_pnl + realized_pnl`), `get_leg_snapshot`, `get_prev_leg_snapshot`, `delete_trade` (no-op if missing; WHERE includes `instrument_key` to prevent wrong-row deletion during rolls), `delete_trade_by_id(trade_id)` (preferred rollback primitive when PaperTrade object unavailable), `create_exit_event` (upsert by trade_id + exit_signal), `get_open_exit_events` (filter by strategy/leg/status), `update_trade_state(trade_id, TradeState)` (raises ValueError if id missing), `record_gate_violation(GateViolation) -> int` / `get_gate_violation_counts(strategy_name=None, gate_name=None) -> list[dict]` (new `gate_violations` SQLite table, indexed on `(strategy_name, gate_name)`; `get_gate_violation_counts` pre-aggregates via `GROUP BY` — never returns raw rows, per Rule 1) — `GateViolation` frozen Pydantic model (`gate_name`, `threshold`, `actual`, `strategy_name`, `logged_at`) records a THRESHOLD IC entry gate (IVR floor, DTE window, liquidity floor, portfolio-delta cap) that would have blocked entry under `--log-only-gates` mode (default True in `paper_ic_entry.py`/`_v2.py`); STRUCTURAL gates (duplicate entry, `_post_expiry_gate`, unresolved instrument, stale/missing VIX window) never produce a `GateViolation` and always hard-block — see `DECISIONS.md` 2026-07-03, `get_proxy_delta_breach_count(strategy_name) -> int` / `set_proxy_delta_breach_count(strategy_name, count)` — persist consecutive days the Proxy deep ITM call delta has been below 0.40 in `paper_strategies` table (`proxy_delta_breach_count INTEGER DEFAULT 0`); reset to 0 on delta recovery. `paper_exit_events` schema captures: strategy_name, leg_name, trade_id, exit_signal (`ExitSignal` enum), severity (INFO/WARN/ACTION), ltp/mid/bid/ask/delta/dte, entry_price, threshold_value, dual-signal audit fields (`delta_stop_would_fire`, `premium_stop_would_fire`, `actual_rule_used`), status (OPEN/ACKNOWLEDGED/ACTED/DISMISSED). `PaperExitEvent` frozen Pydantic model in `src/paper/models.py`. See `src/paper/CLAUDE.md` for full invariants.
`src/strategy/` — paper-backbone strategy layer. `PaperStrategy` protocol (`protocol.py`) + `SignalEvent` + `ApprovedAction` + `LegSpec` models. `ReEntryMixin` (`reentry_mixin.py`): three-gate re-entry check (DTE ≥ 14, IVR ≥ 0.25, no open position); inherited by `CSPNiftyV1`, `CCOverlayV1`, and `CollarOverlayV1`. `StrategyMonitor` (`monitor.py`): registry + tick loop + signal routing + heartbeat + auto-execute dispatch path (strategies with `auto_execute=True` bypass Telegram approval and execute immediately via `PaperExecutor`). `PaperExecutor` (`executor.py`): action dispatch + `PaperFillSimulator` (VIX-regime slippage model). Concrete strategies: `CSPNiftyV1` (`csp_nifty_v1.py`), `IronCondorV1` (`ic_nifty_v1.py`), `NiftyTrackComparisonV1` (`nifty_track_comparison_v1.py`). All implement `PaperStrategy` protocol. `ICExpiryConfig` (`ic_expiry_config.py`): frozen dataclass with per-expiry entry/exit thresholds (delta bounds, wing width, DTE window, profit target, stop-loss multiplier); `CONFIGS` dict provides four presets — `weekly` (DTE≤14, Tuesday bucket), `monthly` (DTE 15–45), `leaps` (DTE 46–200), `yearly` (DTE 201–420); `STRATEGY_IC_WEEKLY/MONTHLY/LEAPS/YEARLY` constants in `src/paper/constants.py`. `IronCondorV1` constructor accepts `ICExpiryConfig`; `strategy_name` is a property (not class attr); `auto_execute=True`; all thresholds sourced from config; `_auto_select_action()` encodes priority (CLOSE_FULL > spread closes). `IronCondorV2ExpiryConfig` (`ic_expiry_config_v2.py`): delta-based config for V2; replaces V1's fixed `wing_width_points` with 10Δ long-wing placement and premium/liquidity floors; `CONFIGS_V2` dict (Phase 1: monthly only); council ruling docs/archive/council/strategy/2026-06-26_ic-v2-core-design.md Stage 3 (D1/D2/D3/D4 decisions). `IronCondorV2` (`ic_nifty_v2.py`): separate strategy class from V1; 25Δ/22Δ entry (D1), 10Δ wings with floors (D2), partial vertical roll adjustment (D3), DTE-tiered exits (D4); `strategy_name` property derives from config.expiry_type; auto_execute=True; 69 KB implementation. `ProfitLockEngine` (`profit_lock_engine.py`): stateless 3-zone evaluator for IC V2 profit-lock decisions; `ProfitLockState` + `ProfitLockDecision` frozen dataclasses; floor formula `max(W,W)+D_cum+D_lock+K ≤ 0.75×C₀` enforced before execution; Zone 1 log-only (25% captured), Zone 2 rolls long wings inward to ~19Δ (50% captured), Zone 3 CLOSE_FULL (75%); auto_execute=True; council ruling docs/archive/council/strategy/2026-06-27_ic-v2-profit-lock-adjustment.md Stage 3. `IronCondorV2ExpiryConfig` updated with `profit_lock: ProfitLockConfig` field; `ProfitLockConfig` frozen dataclass holds zone thresholds, wing delta range (16–22Δ), floor budget 0.75, cost buffer K=10 pts, DTE window 10–22, VIX/IVR guards. `ExitSignalEngine` (`exit_signals.py`): static rule engine for CSP, CC, PP, and Collar overlay rule sets; returns `ExitSignalResult` with severity (INFO/WARN/ACTION). CSP uses 5 independent classmethods (CR1b): `evaluate_profit_target_csp` (LTP ≤ 30% of entry credit = 70% captured), `evaluate_hard_stop_csp` (LTP ≥ 2× entry), `evaluate_delta_breach_csp` (|δ| ≥ 0.40; state-aware: OPEN→DELTA_BREACH, DEFENDED→DELTA_BREACH_FINAL), `evaluate_time_stop_csp` (days_held ≥ 21), `evaluate_roll_eligible_csp` (DTE ≤ 7). `evaluate_cc`: TIME_STOP added, `DTE_REVIEW` replaces `DTE_FORCED`, `_PROFIT_TARGET_RETENTION = Decimal("0.30")` shared with CSP, `_CC_MIN_ENTRY_CREDIT = Decimal("15")` guards PROFIT_TARGET floor. `evaluate_pp`: no bid/ask params; CRASH_MONETIZE (δ ≤ −0.80 OR value ≥ 5× debit, no spread guard); ROLL_ELIGIBLE ACTION at DTE ≤ 5. `evaluate_roll_overlay(leg_role, dte, base_dte, atm_strike)`: ROLL_ELIGIBLE ACTION at DTE ≤ 5 (when base_dte > 10); ROLL_BASE_FIRST WARN when base_dte ≤ 10. `evaluate_proxy_delta(delta, current_mark, dte, consecutive_days)`: three signals for `base_ditm_call` legs — PROXY_DELTA_CRITICAL ACTION (δ<0.40 for 3 consecutive days), PROXY_PREMIUM_DECAY ACTION (mark<₹0.50 with DTE≥5), PROXY_DELTA_WARN WARN (δ<0.65; suppressed when CRITICAL fires). `CSPNiftyV1` (`csp_nifty_v1.py`): always-open design, `auto_execute=True`, full state machine (OPEN/DEFENDED/RE_ENTRY_PENDING via `TradeState`), three action types (CLOSE_AND_ROLL, ROLL_DOWN_AND_OUT, CLOSE_AND_WAIT). Inherits `ReEntryMixin`; re-entry check on PROFIT_TARGET and TIME_STOP exits. `CCOverlayV1` (`cc_overlay_v1.py`): `auto_execute=True`; single action type (CLOSE_CC); inherits `ReEntryMixin`; re-entry check on PROFIT_TARGET and TIME_STOP exits; Telegram notification after close. `PPOverlayV1` (`pp_overlay_v1.py`): `auto_execute=True`; two-state machine (OPEN / RE_ENTRY_PENDING); three action types (MONETIZE_PP, ROLL_PP, OPEN_NEW_PP); IVR ≤ 0.60 re-entry gate (inverted vs CSP/CC — don't buy at peak post-crash IV). Does NOT inherit `ReEntryMixin` (inverted gate requires custom `_evaluate_pp_reentry`). `CollarOverlayV1` (`collar_overlay_v1.py`): `auto_execute=True`; inherits `ReEntryMixin`; atomic close via `OverlayCloser.close_collar_all`. `NiftyTrackComparisonV1` (`nifty_track_comparison_v1.py`): `auto_execute=False` (all overlay and Proxy actions require human confirmation). Wires `evaluate_roll_overlay` (DTE ≤ 5 → ROLL_ELIGIBLE ACTION; base-DTE guard → ROLL_BASE_FIRST WARN). Wires `evaluate_proxy_delta` for `base_ditm_call` legs via `PaperStore.get/set_proxy_delta_breach_count`. `_check_futures_cc_block`: emits BLOCKED_COMBINATION ERROR for standalone short call on `paper_nifty_futures` namespace; collar (short call + paired long put) explicitly exempted. All ACTION-severity `SignalEvent` payloads include `"valid_actions": [...]`, used by `TelegramGateway.send_approval_request` to build the approval keyboard without a council call. `OverlayCloser` (`overlay_closer.py`): atomic multi-leg close orchestrator; `close_collar_all` and `monetize_collar_put` use `store.record_trades([...])` for single DB transaction; `monetize_collar_put` validates put leg exists before touching call (incomplete-collar guard). `auto_close.py` (AUTO-1): EOD auto-close execution via `OverlayCloser` for all overlays, status resolution to ACTED, unified Telegram close notification, EOD PP re-entry eligibility checks (`evaluate_pp_reentry_eod`). `close_ic_legs()` (`ic_close_executor.py`, 2026-07-15): shared auto-close persistence helper for `IronCondorV1`/`IronCondorV2` — batch-fetches live LTP via `broker.get_ltp()`, falls back to the leg's weighted entry price (`avg_sell_price`/`avg_cost`) if unavailable, writes opposite-action closing `PaperTrade` rows atomically via `store.record_trades()`. Called from both classes' `apply_action()` for `CLOSE_FULL`/`CLOSE_CALL_SPREAD`/`CLOSE_PUT_SPREAD` when auto-executing (fixes a bug where those actions filtered the in-memory position list but never wrote the close to `paper_trades`, causing the triggering exit signal to silently re-fire every tick indefinitely — see DECISIONS.md 2026-07-15). `ROLL_WING`/`PROFIT_LOCK_ZONE2` have the same gap on their close side, deferred as IC-CLOSE-2 (TODOS.md) pending replacement-leg strike-selection logic.
